# MSA + SOW

## MSA คืออะไร

MSA = Master Service Agreement
เป็นสัญญาหลักที่กำหนดกติกาใหญ่ เช่น payment, confidentiality, IP, liability, termination

## SOW คืออะไร

SOW = Statement of Work
เป็นเอกสารรายละเอียดงานในแต่ละเฟส เช่น ทำ feature ไหน ส่งเมื่อไหร่ ราคาเท่าไหร่ milestone อะไรบ้าง

## ใช้เมื่อไหร่

เหมาะกับงานที่ทำหลายเฟส หรือมีโอกาสทำต่อเนื่อง เช่น

- Phase 1: Prototype
- Phase 2: MVP
- Phase 3: Multiplayer
- Phase 4: Live Ops
- Phase 5: Maintenance

## ทำไมดี

เพราะไม่ต้องเซ็นสัญญาใหม่ทุกครั้ง
เซ็น MSA ครั้งเดียว แล้วออก SOW ใหม่ตามแต่ละงาน

## จุดที่ต้องระวัง

- MSA เขียน broad มาก แต่ SOW ไม่ชัด
- SOW ไม่มี acceptance criteria
- SOW ไม่บอกว่าอะไรอยู่นอก scope
- ไม่มี change request process
- ไม่มี payment milestone

## โครง SOW ที่ดี

1. Project Name
2. Objective
3. Scope
4. Out of Scope
5. Deliverables
6. Milestones
7. Timeline
8. Payment
9. Acceptance Criteria
10. Client Responsibilities
11. Assumptions
12. Change Request

---

## ฐานทางกฎหมาย

MSA (Master Service Agreement) คือ “สัญญากรอบ” (framework agreement) ที่คู่สัญญาตกลงเงื่อนไขหลักที่จะใช้กับธุรกรรมในอนาคตไว้ล่วงหน้า ส่วน SOW (Statement of Work) คือเอกสารระบุงาน ขอบเขต deliverables ระยะเวลา และราคาของงานแต่ละชิ้น ซึ่งมักออกภายใต้ MSA — โมเดลนี้ใช้กันแพร่หลายโดยเฉพาะงานบริการด้าน IT

ในกฎหมายไทย MSA + SOW ไม่ได้มีชื่อเรียกเฉพาะในประมวลกฎหมาย โดยเนื้อแท้เป็น **สัญญาจ้างทำของ/สัญญาบริการ** (ป.พ.พ. มาตรา 587) ที่จัดโครงสร้างเอกสารแบบแยกกติกากลางออกจากรายละเอียดงานแต่ละเฟส — หลักการตีความและข้อควรระวังจึงเหมือนไฟล์ [01](01-freelance-service-agreement.md) และ [02](02-outsourcing-service-agreement.md)
